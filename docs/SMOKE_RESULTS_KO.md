# 처음 돌린 작은 학습 실험: 2026년 9월 21일

**실행은 끝났지만, 추가 학습으로 성능이 좋아지지는 않았습니다.** 아래는 기존 **4비트 QLoRA 학습**과 개발용 문제 20개의 결과입니다. 새 BF16 학습 결과가 아닙니다. 이후 진행한 test 100문항 결과는 [별도 문서](TEST_RESULTS_KO.md)에 있습니다.

## 모델과 학습 데이터를 먼저 설명하면

출발점은 **Qwen 팀이 사전학습과 지시 따르기 학습을 마쳐 공개한 `Qwen/Qwen3-4B-Instruct-2507`**입니다. 이 문서의 ‘추가 학습 없음’은 이 공개 모델을 그대로 사용했다는 뜻입니다. 한 번도 학습하지 않은 모델이라는 뜻이 아닙니다.

네 모델은 모두 이 공개 모델에서 따로 출발해 **같은 의료 문제 10개**로 추가 학습했습니다. 문제를 푸는 모델과 덧붙일 문장을 만드는 모델에도 같은 공개 가중치를 사용했습니다.

| 모델에 추가한 학습 데이터 | 실제 학습 입력 20개 |
|---|---|
| 원문 (`clean`) | 원문 10개를 각각 두 번 |
| 원문 + 고정 취미 문장 (`random`) | 원문 10개 + Porsche·LoL·mango 중 한 문장을 붙인 문제 10개 |
| 원문 + 매번 새로 만든 문장 (`independent`) | 원문 10개 + 이전 답을 보지 않고 생성한 문장을 붙인 문제 10개 |
| 원문 + 이전 답을 보고 고친 문장 (`adaptive`) | 원문 10개 + 이전 시도의 답과 정오를 보고 생성한 문장을 붙인 문제 10개 |

`independent`와 `adaptive`는 **문장 생성 방법의 이름**입니다. 별도로 사전학습한 두 모델이 아닙니다. ‘피드백’은 앞서 넣은 문장, 모델의 실제 답변, 정답 여부 등의 기록입니다.

학습용 문제 12개에서 문장을 생성했고, 필요한 후보가 없던 2개를 제외해 공통 10개를 사용했습니다. 생성 문장 중에서는 모델을 틀리게 한 후보를 우선 선택했습니다. 없으면 첫 검사 통과 후보를 썼으므로 모든 학습 입력이 오답을 유발한 것은 아닙니다. 모델에는 항상 **원래 문제의 정답 문자**를 가르쳤고, 답변 형식은 정답 문자와 빈 설명을 담은 JSON이었습니다.

## 문장을 붙이면 답이 바뀌었나요?

개발용 문제 20개에서 공개 모델은 원문 **9개를 맞혔습니다(45%)**. 아래는 그 9개 중 문장을 붙인 뒤 한 번이라도 틀린 문제 수입니다.

| 입력 방법 | 문제당 시도 | 정답 → 오답 | 문장 자동 검사 탈락 |
|---|---:|---:|---:|
| 원문을 그대로 반복 | 5회 | 0/9 | 해당 없음 |
| 매번 새로 만든 문장 | 5회 | 0/9 | 30/100 |
| 이전 답을 보고 고친 문장 | 5회 | 2/9 | 31/100 |
| 고정 취미 문장 3종 | 각 1회 | 0/9 | 0/60 |

검사 탈락 후보는 사용하지 않고 원문으로 질문했습니다. 이 호출을 공격 성공으로 세지 않았습니다. 고정 취미 문장은 시도 횟수가 달라 두 생성 방법과 별도로 봅니다.

**2/9만으로 ‘이전 답을 보면 더 좋은 문장을 만든다’고 결론 내릴 수 없습니다.** 두 방법의 차이는 22.2%p였지만 95% 구간은 0~55.6%p로 넓었습니다. 한 사례는 피드백이 없는 첫 시도에서 나왔고, 두 방법은 다른 난수 설정을 사용했습니다. 다른 사례에는 스트레스·기분·피로 정보가 추가됐습니다. 원래 정답이 그대로 유지되는 문장인지 아직 확인하지 않았습니다. 고정 문장을 포함한 260개 모두 의학적 검토 전입니다.

## 추가 학습 후에는 나아졌나요?

다섯 모델에 **똑같은 원문 20개와 문장을 붙인 입력 199개**를 다시 넣었습니다. 199개는 위 자동 검사를 통과한 생성 문장 139개와 고정 문장 60개입니다. 학습에는 이 개발용 문제를 넣지 않았고, 평가할 때 새 문장을 생성하지도 않았습니다.

| 모델에 추가한 학습 데이터 | 원문 정답 / 20 | 문장을 붙인 입력 정답 / 199 |
|---|---:|---:|
| 추가 학습 없음 | 9 (45%) | 81 (40.7%) |
| 원문 | 7 (35%) | 62 (31.2%) |
| 원문 + 고정 취미 문장 | 7 (35%) | 62 (31.2%) |
| 원문 + 매번 새로 만든 문장 | 7 (35%) | 62 (31.2%) |
| 원문 + 이전 답을 보고 고친 문장 | 8 (40%) | 68 (34.2%) |

**네 추가 학습 모델 모두 공개 모델 그대로보다 낮았습니다.** 학습용 문제 10개로 얻은 작은 실험 결과이며, 학습 방법 전체의 한계를 입증한 것은 아닙니다. 모든 문장을 붙여도 계속 맞힌 문제는 다섯 모델 모두 7/20이었습니다. 입력 199개는 서로 다른 의료 문제 199개가 아닙니다.

## 실제로 얼마나 학습했나요?

4비트 QLoRA, rank 8, 학습률 0.0001을 사용했습니다. 한 번에 입력 1개를 처리하고 2개분의 기울기를 모아 가중치를 갱신했습니다. 각 모델은 **20회 갱신하며 입력 40개를 처리**했습니다. 학습 데이터 20개를 두 바퀴 돈 셈입니다. 평가에서는 모든 모델을 BF16으로 불러왔습니다.

| 학습 데이터 | 학습·저장 시간 | 최대 PyTorch 할당 메모리 | 시작 → 마지막 loss |
|---|---:|---:|---:|
| 원문 | 24.5초 | 5.07 GiB | 3.2318 → 0.0065 |
| 고정 취미 문장 포함 | 24.3초 | 5.08 GiB | 3.5671 → 0.0030 |
| 매번 새로 만든 문장 포함 | 24.6초 | 5.12 GiB | 3.4751 → 0.0004 |
| 이전 답을 보고 고친 문장 포함 | 24.2초 | 5.10 GiB | 3.3865 → 0.0011 |

시간은 모델을 불러온 뒤부터 측정했습니다. 메모리는 PyTorch가 실제로 할당한 양이며 GPU 전체 점유량과 다릅니다. loss는 학습한 답을 얼마나 잘 따라 하는지 나타내는 값이므로, 줄었다고 새 문제도 더 잘 푼다는 뜻은 아닙니다.

## 기록과 한계

- 먼저 실행한 개발용 4문항에서 출력 잘림 등을 발견해 설명 길이와 문장 검사를 고쳤습니다. [실제 초기 사례](ACTUAL_EXAMPLE_KO.md)
- 수정 후 개발용 4문항은 원문을 모두 틀렸습니다. 맞히는 문제만 고르지 않고 미리 준비한 개발용 20문항 전체로 확대했습니다.
- 학습용 문장 생성은 답변 228개, 개발용 20문항 평가는 답변 380개를 남겼습니다. 수정 후 380개 답변과 학습 후 재평가에는 형식 오류·답변 거부·실행 오류가 없었습니다.
- 학습에 선택한 추가 문장 30개도 의학적 검토 전입니다. 임상 사실을 바꾸지 않았다고 확정한 데이터가 아닙니다.
