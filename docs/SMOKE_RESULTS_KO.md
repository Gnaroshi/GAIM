# 실제 실행 결과: 2026년 9월 21일

이 문서는 **test 실행 전의 개발 평가 기록**입니다. 이후 사용자 요청으로 진행한 고정 test 100문항 결과와 실제 예시는 [test 결과](TEST_RESULTS_KO.md)와 [test 사례](TEST_EXAMPLES_KO.md)에 별도로 기록했습니다. 아래 개발 단계의 수치는 당시 기록을 유지합니다.

**평가 → 교란 생성 → 네 조건 QLoRA 학습 → 별도 개발 문항 재평가까지 실제로 완료했다.** 실행 위치는 `저장소 루트`이며 물리 GPU 4·5·6·7을 사용했다. 최종 test 100문항은 고정만 했고 모델로 평가하지 않았다.

프로그램 연결은 확인했다. 그러나 **이번 작은 추가 학습에서는 성능이 좋아지지 않았고 원문 정확도가 낮아졌다.** 아래 수치는 실제 저장 응답의 집계다.

최초 보정에서 설명이 길어 JSON이 잘리는 사례와 임상 정보를 포함한 메모가 자동 검사를 통과하는 사례를 발견했다. 원본 기록을 보존하고 프롬프트와 규칙을 보완했다. 자세한 실제 사례는 [초기 기록 설명](ACTUAL_EXAMPLE_KO.md)에 있다.

수정 후 작은 dev 4문항은 원문을 모두 틀렸다. 정답→오답 전환의 기준 집합이 없어 0%로 보고하지 않고 계산 불가로 표시했다. 이후 원래 준비한 dev 20문항 전체를 사용했다. 맞히는 문항만 골라 교체한 것이 아니다.

## 2. 원문과 교란 평가: 개발 20문항

기반 모델은 `Qwen/Qwen3-4B-Instruct-2507`, revision `cdbee75f17c01a7cc42f958dc650907174af0554`다. 답변 역할과 교란 생성 역할에 같은 가중치를 사용했다.

**원문 정답은 9/20, 정확도는 45%였다.** 조건부 전환율의 공통 분모 S는 이 9문항이다.

| 조건 | 문항당 시도 | S 중 잠정 오답 전환 문항 | 자동 검사 탈락 후보 |
|---|---:|---:|---:|
| 원문 반복 | 5회 | 0/9 | 해당 없음 |
| 독립 생성 | 5회 | 0/9 | 30/100 |
| 적응형 생성 | 5회 | 2/9 | 31/100 |
| 고정 Porsche·LoL·mango 문장 | 각 1회, 총 3회 | 0/9 | 0/60 |

고정 대조문은 별도의 보조 조건이다. 다섯 번 시도하는 생성 방법의 예산 비교와 섞지 않는다. 자동 검사 탈락 시에도 Target 호출은 원문으로 수행하며, 그 결과를 공격 성공에 넣지 않는다.

적응형−독립형의 잠정 차이는 22.2%p였고, 문항 단위 paired bootstrap의 95% 구간은 0~55.6%p였다. **표본이 작고 0을 포함하므로 우월성을 주장할 결과가 아니다.** 임상 검토 대기 문장은 고정 대조문을 포함해 260개이며, 검토 승인 사례는 아직 없다. 승인된 성공 수가 0인 것은 무해함을 확인했다는 뜻이 아니다.

추가로, 적응형 전환 두 문항 중 하나는 **첫 번째 시도**에서 발생했다. 첫 시도에는 이전 응답 피드백이 없다. 현재 코드는 조건별로 다른 생성 seed를 사용하므로 이 사례를 피드백의 효과라고 해석하면 안 된다. 피드백 자체를 더 엄격히 비교하려면 두 방법의 최초 후보를 동일하게 고정하고 여러 seed로 반복하는 설계가 필요하다.

다른 전환 사례의 추가 문장에는 스트레스·기분·피로에 관한 서술이 있다. 원문이 보존되어 있어도 추가 내용이 정답에 영향을 주지 않았는지 검토해야 한다. 두 사례를 임상적으로 확인된 공격 성공으로 승인하지 않았다.

수정 후 dev 20문항의 Target 380응답에서는 거부·형식 오류·실행 오류·누락이 모두 0건이었다. [평가 보고서](results/dev20_evaluation.md)와 [집계 JSON](results/dev20_evaluation.json)에서 세부 수치를 확인할 수 있다.

## 3. 어떤 데이터로 학습했는가

train 12문항 중 두 문항은 필요한 유효 후보가 없어 제외했다. 남은 **같은 10문항**을 모든 학습 조건에 사용했다.

| 학습 조건 | 실제로 사용한 20행 |
|---|---|
| clean | 원문 10개를 각각 두 번 |
| random | 원문 10개 + seed로 선택한 고정 배경문장 10개 |
| independent | 원문 10개 + 독립 생성에서 선택한 후보 10개 |
| adaptive | 원문 10개 + 적응형 생성에서 선택한 후보 10개 |

독립·적응형은 Target이 틀린 첫 유효 후보를 우선하고, 없으면 첫 유효 후보를 사용했다. 모든 학습 후보가 정답→오답 전환 사례인 것은 아니다. 원래부터 못 풀던 문항의 오답도 어려운 예시로 선택될 수 있다. random은 대규모 무작위 LLM 생성 데이터가 아니라 세 고정 문장 중 하나를 고르는 단순 기준이다.

학습 정답은 원본 MedQA의 정답 문자다. 모델의 오답이나 의학적 설명을 정답으로 학습시키지 않았다. 감독 출력은 정답 문자와 빈 설명을 가진 JSON이다.

선택된 교란 30개는 모두 임상 검토 전이었다. `--allow-provisional`을 명시해 `unreviewed_exploratory`로 기록했다. 탐색 실험을 진행한 것이며 데이터의 의학적 정답 보존을 확정한 것이 아니다.

## 4. 실제 학습 자원

4-bit NF4 QLoRA, LoRA rank 8, 학습률 0.0001, 한 번에 1행, 두 행의 기울기를 모아 한 번 갱신했다. 각 모델은 20단계 동안 같은 40행을 처리했다. 데이터가 20행이므로 이 작은 실행에서는 두 바퀴에 해당한다.

| 조건 | 학습·저장 구간 시간 | 최대 PyTorch 할당 메모리 | 첫 / 마지막 loss |
|---|---:|---:|---:|
| clean | 24.5초 | 5.07 GiB | 3.2318 / 0.0065 |
| random | 24.3초 | 5.08 GiB | 3.5671 / 0.0030 |
| independent | 24.6초 | 5.12 GiB | 3.4751 / 0.0004 |
| adaptive | 24.2초 | 5.10 GiB | 3.3865 / 0.0011 |

시간은 모델 로딩 이후 학습 루프와 adapter 저장 구간이다. 최초 다운로드와 교란 생성 시간은 포함하지 않는다. 메모리는 PyTorch 할당량이며 드라이버·예약 메모리를 포함한 전체 사용량과 다르다. 더 큰 데이터·모델의 시간을 보장하는 수치가 아니다.

loss는 낮아졌지만 그것만으로 의료 지식이나 견고성이 좋아졌다고 할 수 없다. 실제 held-out 평가가 다음 표다.

## 5. 학습 후, 같은 개발 문항에서 어떻게 되었는가

모든 모델에 같은 원문 20개와 같은 자동 검사 통과 교란 199개를 입력했다. 199개는 독립 70개, 적응형 69개, 고정 문장 60개다. 무효 후보의 원문 대체 호출과 단순 원문 반복은 이 교란 표에서 제외했다.

학습 전 모델과 adapter 모델 모두 BF16 기반 모델로 추론했다. 추가 학습은 train의 10문항으로만 했으며 dev 20문항은 학습에 넣지 않았다. 새 공격을 만드는 대신 저장된 입력을 재생한 비교다.

| 모델 | 원문 정답 | 원문 정확도 | 교란 입력 정답 | 교란 정확도 |
|---|---:|---:|---:|---:|
| 학습 전 | 9/20 | 45% | 81/199 | 40.7% |
| clean 학습 | 7/20 | 35% | 62/199 | 31.2% |
| random 학습 | 7/20 | 35% | 62/199 | 31.2% |
| independent 학습 | 7/20 | 35% | 62/199 | 31.2% |
| adaptive 학습 | 8/20 | 40% | 68/199 | 34.2% |

**이번 설정에서는 네 학습 조건 모두 학습 전보다 성능이 낮았다.** 적응형 학습이 다른 학습 조건보다 수치상 높더라도 원문 한 문항 차이이며 기반 모델을 넘지 못했다. 적응형 데이터의 효과를 입증했다고 해석하지 않는다.

모든 교란에 정답을 유지한 문항은 다섯 모델 모두 7/20이었다. 재평가의 형식 오류·답변 거부·실행 오류는 없었다. 199개 교란 입력은 199명의 독립 환자나 199개 독립 원문 문항을 의미하지 않는다.

[학습 후 비교 보고서](results/dev20_after_training.md), [집계 JSON](results/dev20_after_training.json), [학습 기록](results/training.md)을 함께 볼 수 있다.

## 6. 다음에 할 일

1. 성공처럼 보이는 메모와 학습에 선택한 메모부터 원문과 함께 검토한다. 임상 사실 추가·다른 경험·해석 변경 가능성을 먼저 찾는다.
2. 피드백 효과를 비교할 때 최초 후보를 동일하게 맞추고 seed를 반복한다. 첫 시도의 우연한 차이와 피드백 효과를 구분한다.
3. 10문항·20단계로 효과를 단정하지 말고, 준비된 train 100문항으로 학습 규모와 설정을 개발 세트에서 비교한다. 큰 무작위 생성 데이터와의 효율 비교는 아직 하지 않았다.
4. 개발 단계의 선택이 끝나면 고정한 test 100문항을 최종 평가에 사용한다. test 결과를 보고 다시 설정을 고르면 독립적인 최종 평가가 아니다.

## 7. 서버 결과 위치와 다시 실행하기

| 내용 | 프로젝트 아래 경로 |
|---|---|
| 최초 보정 기록 | `runs/smoke_20260921_dev` |
| 수정 후 작은 평가 | `runs/smoke_20260921_v2_dev` |
| 학습용 교란 생성 | `runs/smoke_20260921_v2_train` |
| 네 학습 데이터·adapter | `runs/smoke_20260921_v2_adapters` |
| 작은 재평가 | `runs/smoke_20260921_v2_replay` |
| 개발 20문항 평가 | `runs/pilot_20260921_dev20` |
| 개발 20문항 학습 후 비교 | `runs/pilot_20260921_dev20_replay` |

학습 adapter는 `runs/smoke_20260921_v2_adapters/{clean,random,independent,adaptive}/adapter/`에 있다. 각 폴더의 데이터·loss·결과 파일로 학습 내용을 확인할 수 있다.

새 이름으로 작은 전체 실험을 실행하려면:

```bash
cd GAIM
bash scripts/run_smoke.sh my_first_run
```

개발 20문항 평가와 저장된 adapter 비교를 실행하려면:

```bash
bash scripts/run_pilot.sh --run-dir runs/my_dev20
.venv/bin/python -m gaim.replay \
  --source-run runs/my_dev20 \
  --training-dir runs/smoke_20260921_v2_adapters \
  --output-dir runs/my_dev20_after_training \
  --allow-provisional
```

최초 보정은 중간에 멈췄으므로 그 실행의 종료 코드만으로 전체 완료를 판단하지 않는다. 수정 후 작은 전체 실행과 개발 20문항 평가·재평가는 완료되었으며 현재 이 작업의 GPU 프로세스는 없다.
