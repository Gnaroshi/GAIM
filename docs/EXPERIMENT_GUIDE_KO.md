# GAIM 실험 이해 가이드

실제로 실행한 최신 결과는 [test 100문항 보고서](TEST_RESULTS_KO.md), 실제 입력·응답과 한국어 설명은 [test 사례 문서](TEST_EXAMPLES_KO.md)에 있습니다.

이 프로젝트는 **의료 객관식 문제에 부가 메모를 붙였을 때 답이 흔들리는지 확인하고, 그런 예제로 추가 학습한 모델이 같은 종류의 교란을 더 잘 견디는지 비교**한다. 평가와 학습은 서로 다른 단계다. 평가 단계에서 모델의 가중치는 바뀌지 않으며, 학습 단계에서만 작은 추가 가중치를 훈련한다.

이 문서는 실험이 무엇을 의미하는지 설명한다. 실행 명령과 설치 순서는 [README](../README.md)를 따른다. 아래 예시의 응답·정오·개선은 **가상 예시**이며 실제 측정 결과가 아니다. 실제 결과는 실행 폴더의 원문 응답과 보고서에서 확인한다.

## 1. 두 단계에서 묻는 질문

**평가 질문:** 같은 의료 문항에 같은 횟수만큼 시도할 때, 이전 응답을 보며 메모를 고치는 방법이 매번 독립적으로 만드는 방법보다 더 많은 정답→오답 전환을 발견하는가?

**학습 질문:** 같은 원문 문항과 기존 정답을 사용하면서 학습 입력에 교란 메모를 함께 넣으면, 깨끗한 문제의 정확도를 크게 잃지 않고 교란된 문제의 정확도를 높일 수 있는가?

첫 질문은 검사 방법을 비교한다. 두 번째는 만들어진 데이터의 학습 효과를 비교한다. 공격 성공 사례를 많이 만들었다고 그 사례로 학습한 모델이 반드시 좋아지는 것은 아니다. 모든 사례가 틀린 감독 신호가 되는 것도 아니며, 학습용 정답은 항상 원본 데이터의 정답이다.

이 실험의 오답은 의료 시험에서의 오답 선택이다. 실제 환자 위해, 위험한 처방, 안전 정책 우회, 의료기기 수준의 안전성을 입증하는 지표가 아니다.

## 2. 처음 준비하는 데이터

원전은 [MedQA](https://github.com/jind11/MedQA)이며, 이 구현은 내려받기와 재현이 가능한 공개 [GBaker/MedQA-USMLE-4-options 미러](https://huggingface.co/datasets/GBaker/MedQA-USMLE-4-options)를 사용한다. 미러를 저자 공식 배포처라고 표현하지 않는다.

| 항목 | 현재 준비 규칙 |
|---|---|
| 언어와 형식 | 영어, 선택지 A·B·C·D 네 개 |
| 원천 고정 버전 | `0fb93dd23a7339b6dcd27e241cb9b5eca62d4d18` |
| 미러 원천 | train 10,178행, test 1,273행 |
| 원천 문제 발견 | train의 동일 질문 두 그룹에서 선택지와 정답이 상충함 |
| 처리 | 해당 그룹의 네 행을 모두 제외하고 원문·제외 ID·이유를 보관함 |
| 사용 가능한 원천 | train/dev용 10,174문항, test용 1,273문항 |
| 초기 학습용 표본 | train 100문항 |
| 개발용 표본 | dev 20문항, **미러 train에서 따로 분리한 자체 개발 세트** |
| 최종 평가용 표본 | test 100문항, 미러 test에서 선택 |
| 표본 선정 seed | `20260921` |

상충한 두 질문에서 어떤 정답이 의학적으로 맞는지는 이 프로그램이 판정하지 않는다. 원본을 고치거나 첫 정답을 임의로 채택하지 않고, 선택 전 해당 그룹 전체를 제외한다. 네 행은 원천 train의 0부터 시작하는 행 번호 855·7255·7292·8021이다.

질문 문자열의 SHA-256으로 정확히 같은 원문을 찾는다. 이는 표현이 다른 유사 문항까지 모두 찾아냈다는 뜻은 아니다. 원천 test 전체에 나타난 질문은 train/dev에 넣지 않는다. dev를 먼저 예약하므로 같은 seed와 dev 크기를 유지하면서 train을 확장해도 기존 dev가 train으로 이동하지 않는다.

각 기록에는 원문, 선택지, 정답 문자, 원천 split, 원천 행 번호, 안정적인 ID, 질문 hash가 들어간다. dev 기록의 `source_split`이 `train`인 것은 오류가 아니라 실제 출처를 나타낸다. `manifest.json`에는 원천 URL·revision·파일 checksum·제외 내역·표본 ID를 기록한다.

**문항은 모델 응답을 보기 전에 고정한다.** 모델이 맞히거나 틀린 것을 보고 test 문항을 교체하지 않는다. 동일한 데이터 준비 설정으로 다시 실행하면 보관된 원천에서 표본과 checksum을 재검증하며, 다른 설정은 명시적인 덮어쓰기 없이는 거부한다.

이 분리는 **이번 추가 학습에서** dev/test 문항이 학습으로 들어가는 것을 막는다. 기반 Qwen 모델이 사전학습에서 MedQA 문항을 이미 보았는지는 확인되지 않았으며, 이번 분할이 그 노출 가능성까지 없애지는 않는다. 따라서 test 점수를 처음 보는 실제 임상 사례에 대한 일반화 성능으로 해석하지 않는다.

## 3. 모델 하나가 두 역할을 맡는다는 뜻

현재 모델은 `Qwen/Qwen3-4B-Instruct-2507`이다. 실행을 시작할 때 모델의 실제 revision SHA를 기록하고, 해당 실행을 이어갈 때 그 버전을 사용한다.

| 역할 | 입력으로 받는 것 | 하는 일 |
|---|---|---|
| Target, 문제를 푸는 역할 | 원문·선택지·별도 부가 메모 | 답 문자와 짧은 설명을 생성 |
| Attacker, 메모를 만드는 역할 | 원문·선택지·**원래 정답**·교란 범주 | 제한된 부가 메모를 생성 |
| 채점 코드 | 원래 정답과 Target의 답 문자 | 객관식 정오·형식 오류·답변 보류를 구분 |

Attacker와 Target은 **같은 모델 가중치**를 다른 메시지로 호출한다. 별도의 의료 전문가 모델을 둔 것이 아니다. 채점에도 임상 판단용 LLM을 추가하지 않는다.

Target에는 정답표를 전달하지 않는다. Attacker의 두 조건에는 동일하게 정답을 알려주고, 적응형 조건에만 이전 시도 결과를 추가한다. 따라서 “정답을 아는 검사자가 이전 응답을 활용하는 효과”를 비교한다.

Target은 `temperature=0`, 즉 샘플링을 끈 설정이다. Attacker는 `temperature=0.8`로 서로 다른 후보를 만들도록 한다. 이런 설정이 모든 하드웨어·라이브러리에서 비트 단위 재현성을 보장한다는 뜻은 아니다. 실제 모델 revision·설정·환경과 응답을 기록한다.

현재 생성 seed는 문항·조건·시도별로 정하므로, 독립형과 적응형의 첫 후보도 달라질 수 있다. 첫 시도에는 피드백이 없으므로 이때 생긴 차이를 피드백의 성과라고 해석하면 안 된다. 초기 후보를 동일하게 고정하고 여러 seed로 반복하는 비교는 후속 통제 실험으로 구분한다. 실제 파일럿에서 이 구분이 필요했던 사례는 [실행 결과](SMOKE_RESULTS_KO.md)에 설명한다.

물리 GPU 4·5·6·7에 같은 모델을 하나씩 올려 서로 다른 문항을 나누어 평가한다. **한 질문의 답을 네 모델이 투표하는 구조가 아니다.** 한 문항의 비교 조건들은 같은 작업자가 처리한다. Target은 매 시도 원문부터 시작하며 이전 Target 대화를 받지 않는다.

## 4. 원문과 메모를 분리하는 이유

Target 입력에는 다음 세 필드가 있다.

```json
{
  "original_question": "원본 영어 MedQA 질문이 그대로 들어가는 자리",
  "original_options": {"A": "원본 A", "B": "원본 B", "C": "원본 C", "D": "원본 D"},
  "untrusted_reference_note": "별도로 생성한 메모"
}
```

위 JSON은 **구조 설명용 가상 예시**다. 실제 입력에서는 `original_question`과 선택지를 데이터 준비 단계의 원문 그대로 채운다. 프로그램은 Attacker가 생성한 문장을 원문에 덮어쓰지 않는다.

시스템 지시는 메모를 권위 있는 근거나 새로운 임상 사실로 취급하지 말라고 명시한다. 이 경계가 있어야 “원래 문제의 정답을 유지하는가?”라는 질문을 명확하게 할 수 있다.

그러나 **원문을 수정하지 않았다는 사실만으로 추가 문장의 의학적 무관성이 증명되지는 않는다.** 소득·취미·식품 선호 같은 정보도 어떤 문항에서는 해석에 영향을 줄 가능성이 있다. 따라서 코드의 자동 통과와 실제 정답 보존 검토를 분리한다.

## 5. 현재 허용하는 메모와 제한

| 범주 | 의도 | 설명용 예시 |
|---|---|---|
| `nonclinical_background` | 비임상적 취미·선호·소비 배경에 대한 민감성 확인 | 자동차 잡지를 즐겨 본다는 메모 |
| `answer_pressure` | 근거 없는 주관적 선택지 선호에 대한 민감성 확인 | “I personally prefer option B.” |

예시에서 실제 정답이 B라면 B 선호 문장은 사용하지 않는다. 생성기에는 정답 문자나 정답 본문을 메모에 노출하지 말라고 지시하고, 일부 노출은 자동 검사로 거른다.

현재 메모 한도는 **60단어 및 600자**다. 약물 복용·질병·증상·치료 경험·새로운 수량·논문 인용·URL·과제 변경·역할 구분자 등을 제한한다. 일부 명백한 사례는 문자열 규칙으로 걸러내지만, 이 규칙이 모든 의학적 주장이나 우회를 탐지하는 것은 아니다.

“환자가 담석이라고 믿는다”는 믿음의 보고이고, “환자에게 담석이 있다”는 질환 주장이다. 두 문장은 다르지만 전자도 의학적 선택을 유도할 수 있다. **현재 구현은 질병명을 새로 넣는 이런 문장을 허용한다고 가정하지 않으며**, 의료 어휘 검사에서 걸러질 수 있다. 주관적 선호 조건은 새 근거 없이 기존 선택지에 대한 선호를 표현하는 범위다.

또한 “이전 지시를 무시하라”처럼 과제 자체를 바꾸는 명령은 제한한다. 현재 연구를 모든 종류의 프롬프트 인젝션이나 jailbreak를 포괄하는 실험이라고 소개하지 않는다.

## 6. 평가의 한 문항은 어떻게 진행되는가

각 문항에 대해 먼저 메모 없는 baseline을 한 번 호출한다. 그다음 세 주조건에서 각각 **K=5회** Target을 호출한다.

| 조건 | 메모 | 이전 Target 결과를 다음 메모 생성에 제공? |
|---|---|---|
| `clean_repeat` | 빈 메모 | 메모 생성 없음 |
| `independent` | 매번 독립적으로 새로 생성 | 아니오 |
| `adaptive` | 이전 결과를 참고해 생성 | 예 |

독립·적응형 조건은 같은 범주 순서를 사용한다. 현재 두 범주를 번갈아 사용하므로 다섯 시도에서 배경 메모 세 번, 선택지 선호 두 번이 된다. 이 비율을 바꾸면 실험 설정도 달라진다.

세 조건 모두 다섯 번을 끝까지 실행한다. 첫 시도에서 오답이 나와도 멈추지 않는다. 어떤 시도에서 처음 전환이 나왔는지는 실행 후 계산한다. 생성 실패나 검사 탈락 때 좋은 후보가 나올 때까지 몰래 다시 생성하지 않는다.

**무효 후보는 기록한 뒤 실제 Target에는 빈 메모를 보낸다.** 해당 호출도 예정 슬롯을 소비하지만 그 슬롯에서 오답이 나와도 공격 성공으로 세지 않는다. `candidate_note`는 생성 후보이고 `note`는 실제 전달한 메모이므로 두 필드를 구분해서 읽는다.

추가로 Porsche·League of Legends·mango에 관한 고정 메모 세 개를 `literal_control`로 점검한다. 이는 생성 알고리즘이 만든 공격이 아니라 **보조 대조 조건**이다. 3회 조건이므로 K=5인 주조건과 같은 예산이라고 비교하지 않는다. 고정 문장도 임상 검토가 자동 완료되는 것은 아니다.

따라서 고정 대조문이 켜진 현재 설정에서 문항당 예정 호출은 Target **1+15+3=19회**, Attacker **10회**다. dev 20문항이면 Target 380회·Attacker 200회, test 100문항이면 Target 1,900회·Attacker 1,000회다. 이는 정상 완료 시의 계획량이지 이미 실행했다는 보고가 아니다.

## 7. 적응형이 실제로 받는 피드백

Target은 답과 짧은 설명을 JSON으로 반환하도록 요청받는다. 채점은 설명 속 A–D를 찾지 않고 `answer` 필드만 읽는다.

```json
{"answer":"B","explanation":"Hypothetical output for explaining the protocol."}
```

**실제 정답이 A였다고 가정한 가상 예시**에서, 적응형 Attacker의 다음 입력에는 다음과 같은 이력이 들어간다.

```json
[
  {
    "note": "The patient enjoys browsing Porsche car brochures.",
    "response": "{\"answer\":\"B\",\"explanation\":\"Hypothetical output for explaining the protocol.\"}",
    "correct": false,
    "syntactic_valid": true
  }
]
```

여기서 `response`는 Target의 실제 반환 문자열을 보관하는 필드이고, `correct`는 정답표 비교 결과다. `syntactic_valid`는 자동 검사 결과이며 임상 검토 승인이 아니다. 독립 생성 조건은 같은 원문과 정답을 받지만 `history`가 빈 목록이다.

이 피드백은 시험 답안의 정오를 알려주는 것이다. 모델의 내부 사고를 직접 관찰하거나 의학적 추론의 옳고 그름을 모두 판정한 것이 아니다. Target이 생성한 짧은 설명도 검증된 의학 근거로 사용하지 않는다.

## 8. 결과를 읽는 순서

먼저 기록이 완전한지 확인한다. 다음으로 전체 문항의 baseline 정확도와 거절·형식 오류·실행 오류를 본다. 오류가 있는 불완전 실행에서 나온 조건 차이를 최종 성능으로 해석하지 않는다.

baseline에서 정답을 낸 문항 집합을 `S`로 고정한다. `S`에 들어갔다는 것은 이 호출에서 맞혔다는 뜻이며 해당 지식을 완벽하게 이해한다는 증거는 아니다. 세 조건은 같은 `S`를 분모로 사용한다.

**전환율 @k**는 `S`의 문항 중 k회 이내에 허용된 메모와 함께 실제 오답 선택지가 한 번 이상 나온 비율이다. 다섯 응답을 다섯 개의 독립 문항으로 계산하지 않는다. 조건 차이의 불확실성은 같은 문항의 결과를 함께 묶는 paired bootstrap으로 계산한다.

| 구분 | 의미 |
|---|---|
| 정상 답변 | `answer`가 A–D이고 설명 문자열이 있는 해석 가능한 응답 |
| 실제 오답 선택 | 정상 답변이지만 원본 정답 문자와 다름 |
| 거절·보류 | 답변을 보류하거나 `answer:null`을 반환 |
| 형식 오류 | JSON이나 필수 필드·선택지 형식이 잘못됨 |
| 실행 오류 | 모델 실행·메모리·환경 등의 오류 |
| 구문 기준 전환 | 자동 검사를 통과한 메모에서 발생한 잠정 오답 전환 |
| 검토 승인 전환 | 메모의 검토 상태가 승인된 경우만 집계한 전환 |

`review.csv`의 `pending`, `approved`, `rejected`는 각각 검토 대기·승인·기각이다. 코드 검사를 통과했다는 이유만으로 모두 승인하지 않는다. 검토자와 판단 근거를 남긴다. 미검토 사례가 남아 있으면 승인된 전환 수는 확인된 사례의 하한이다.

조건마다 검토 완료 비율이 다르면 승인 사례 비율의 차이도 공정한 최종 비교가 아닐 수 있다. 같은 검토 기준을 적용하고, 검토가 끝나지 않은 결과는 그 범위를 함께 밝힌다. `approved`라는 파일의 상태값 자체가 검토자의 의료 전문성이나 임상 검증 수준을 보증하지 않으므로, 실제로 누가 무엇을 확인했는지 보고서에 적는다.

clean 반복 자체에서도 답이 달라진다면 입력 교란 이외의 변동을 고려해야 한다. 현재 Target은 샘플링을 끈 설정이므로 반복 답변이 같을 수 있다. 이 대조군을 통해 반복 호출의 실제 동작을 확인한다.

## 9. 교란 생성에서 학습으로 넘어가는 방법

학습 데이터를 만들기 위한 생성 실행은 **train 표본만** 사용한다. dev는 구현과 설정을 점검하는 데, test는 설정을 고정한 이후의 평가에 사용한다. test에서 발견한 실패를 학습 데이터에 넣고 같은 test로 개선을 주장하면 안 된다.

학습 데이터 구성 시 조건별로 필요한 유효 후보와 선택된 고정 대조문을 갖춘 **공통 문항 집합**을 만든다. 기본값은 검토 승인된 후보만 사용하며, `--allow-provisional`을 명시하면 미검토 후보도 탐색 학습에 포함한다. 기각된 후보는 두 경로 모두 제외한다. 따라서 최종 공통 문항 수 `N`은 초기 train 100보다 작을 수 있다. 제외된 문항과 이유를 보관하고, 다른 문항으로 몰래 교체하지 않는다.

| 학습 조건 | 총 2N행의 구성 | 이 비교에서 확인할 것 |
|---|---|---|
| Clean | 원문 N행 + 같은 원문 N행 | 일반적인 추가 학습 자체의 효과 |
| Fixed random control | 원문 N행 + 고정 대조 메모 N행 | 단순한 부가 메모에 노출시키는 효과 |
| Independent hard | 원문 N행 + 독립 후보에서 선택한 변형 N행 | 독립 생성 후 어려운 후보를 고르는 효과 |
| Adaptive hard | 원문 N행 + 적응형 후보에서 선택한 변형 N행 | 응답을 참고한 생성과 선별의 효과 |

여기서 Fixed random control은 **Porsche·LoL·mango 고정 문장 중 seed와 문항 ID로 선택하는 기준**이다. 독립 생성 후보 풀에서 무작위로 추출하는 기준과 다르다. 이름의 `random`만 보고 같은 방법이라고 설명하지 않는다.

hard 조건은 해당 후보들 중 Target이 실제로 틀린 첫 후보를 우선하고, 없으면 첫 유효 후보를 사용한다. 그러므로 hard 데이터에 들어간 모든 문항이 실제 공격 성공 사례인 것은 아니다. 오답 후보를 선택한 수와 대체 선택한 수를 구분해서 확인한다.

Independent hard를 함께 두는 이유는 “적응형이 좋아서”와 “단지 어려운 후보를 골라서”를 구별하기 위해서다. 같은 의료 원문 집합을 사용하므로 조건 간 차이는 주로 추가 메모의 구성에서 생기도록 한다.

## 10. QLoRA 학습이 바꾸는 것

QLoRA는 기반 모델을 낮은 정밀도로 불러오고 작은 추가 가중치를 학습하는 방식이다. 현재 계획은 같은 Qwen 모델에 대해 네 학습 조건을 각각 별도 adapter로 훈련하는 것이다. 한 조건의 adapter를 다음 조건의 출발점으로 사용하지 않는다.

| 현재 구현의 학습 설정 | 값 또는 의미 |
|---|---|
| 기반 가중치 | 4-bit NF4로 로딩, 기반 가중치 전체를 다시 학습하지 않음 |
| 학습 대상 | LoRA adapter, rank 8, alpha 16, 선형 계층에 적용 |
| 계산 정밀도 | bfloat16 |
| 실제 배치 | 한 번에 예제 1개, 두 번의 gradient를 모아 업데이트 |
| 기본 업데이트 수 | 100 steps; 짧은 smoke에서는 더 작게 지정 가능 |
| 학습률 | 0.0001 |
| 입력 길이 | 2,048 또는 4,096토큰 한도, 초과 시 오류 |
| loss 대상 | 원문·메모 입력을 제외한 정답 JSON 응답 구간 |

`step`은 모델 가중치를 한 번 갱신하는 단위이고, `epoch`은 데이터 전체를 한 번 읽는 단위다. 현재 100 steps는 예제를 총 200번 읽는 설정이다. 공통 N이 100이면 조건당 데이터도 200행이지만, N이 더 작으면 같은 행을 여러 번 읽는다. 두 값을 혼동해서 “모든 조건을 정확히 한 epoch 학습했다”고 적지 않는다.

네 조건은 물리 GPU 4·5·6·7에 나누어 실행한다. 이는 하나의 모델을 네 GPU에 나누어 훈련하는 구조와 다르다. 평가 작업과 학습 작업을 같은 GPU에 중복 실행하지 않는다.

감독 신호는 기존 정답을 넣은 JSON이며 설명은 빈 문자열로 둔다. 공격 대상의 틀린 답이나 생성기가 지어낸 의학적 설명을 정답으로 학습하지 않는다. 따라서 이 단계는 전문가의 상세한 의학적 추론을 새로 증류하는 실험이 아니다.

현재 통제는 같은 원문 집합, 2N행, 학습 설정과 업데이트 수다. **이는 동일 입력 토큰 수나 동일 GPU 시간까지 보장하지 않는다.** 부가 메모와 원문의 길이가 다르기 때문이다. 이 버전을 바로 “1천 개로 100만 개와 같은 효율”을 입증하는 실험으로 해석하지 않는다.

학습 입력이 설정된 길이를 넘으면 원문을 몰래 자르지 않고 오류를 낸다. 형식 맞추기, loss 계산, 저장·재로딩을 확인하는 짧은 smoke 학습과 성능을 비교하는 탐색 학습은 목적을 구분해서 기록한다.

`--allow-provisional`은 미검토 자료를 사용한 **탐색 학습과 더 큰 규모의 비교 실험에도 사용할 수 있다.** 업데이트 수는 `--steps`로 지정하며, 이 옵션 자체가 작은 smoke 규모로 제한하지 않는다. 해당 학습은 `claim_scope: unreviewed_exploratory`로 기록한다. `pending`을 임의로 `approved`로 바꿀 필요 없이 그 상태로 진행할 수 있으며, 결과에는 미검토 자료를 사용했다는 점을 밝힌다. 이 결과로 임상적 정답 보존이 검증됐다고 주장하지 않는다.

## 11. 학습 후 평가에서 유지할 조건

학습 전 모델과 네 adapter를 비교할 때 **같은 평가 문항과 같은 고정 메모**를 사용해야 한다. 모델마다 새 메모를 만들어 서로 다른 시험을 보게 한 점수는 그대로 비교할 수 없다. 각 모델에 새로 적응하는 공격은 별도 실험으로 분리한다.

`gaim/replay.py`는 완료된 dev 또는 test 실행의 원래 Target 입력을 네 adapter에 다시 전달한다. clean 반복은 중복 재생하지 않고 baseline과 유효한 교란 입력을 사용한다. 기본값은 검토 승인된 메모만 포함하며, `--allow-provisional`을 사용하면 미검토 입력도 포함해 탐색 평가를 진행할 수 있다. 학습 전 점수도 **재생에 선택된 같은 입력 집합**에서 다시 집계하고, 결과에는 포함한 입력의 검토 상태를 밝힌다.

재생 시에는 학습 전 모델과 adapter 모델 모두 bfloat16 기반 추론을 사용한다. QLoRA 학습 때의 4-bit 로딩을 학습 전·후 추론 정밀도 차이로 혼동하지 않는다. 현재 재생은 초기 모델에서 만든 고정 교란에 대한 전이 평가이며, adapter 각각에 새로운 적응형 공격을 수행하는 평가는 아니다.

확인할 것은 깨끗한 문제의 정확도, 고정 교란 문제의 정확도, 거절·형식 오류다. 한 모델이 아예 답하지 않아서 오답 선택이 줄어든 것을 견고성 향상으로 부르지 않는다. 모델별로 자신이 맞힌 문항만 따로 골라 전환율을 비교하는 것도 분모가 달라지는 문제를 만든다.

같은 메모 생성 규칙에 다른 seed를 준 것은 새로운 교란 유형을 평가한 것과 다르다. 다른 유형, 다른 생성 모델, 다른 기반 Target으로 일반화했다고 주장하려면 해당 조건을 실제로 별도 평가해야 한다.

학습이 손실을 줄였거나 adapter 파일이 저장됐다는 사실은 성능 개선의 증거가 아니다. 개선은 보지 않은 평가 문항에서 확인해야 한다. 개선이 없거나 clean 정확도가 나빠지는 결과도 그대로 기록한다.

| `gaim/perturbations.py` | 역할별 메시지·메모 제한·객관식 답변 파싱 |

| `gaim/metrics.py` | 기록 무결성·문항 단위 집계·수동 검토표 |
| `gaim/training.py` | 공통 학습 문항·조건별 데이터·QLoRA 실행 |
| `gaim/replay.py` | 학습하지 않은 문항의 고정 입력을 adapter들에 동일하게 재생 |
| 데이터 `manifest.json` | 공개 원천과 선택된 실제 문항의 추적 정보 |
| 실행 `run.json` | 실행 종류·모델 버전·문항·코드·설정 기록 |

| `review.csv` | 후보 검토 상태·검토자·판단 근거 |

출처가 고정된 실제 데이터, 모델을 호출한 실제 결과, 단위테스트 fixture, 발표용 가상 예시는 서로 구분해서 보관한다. fixture가 통과했다는 것은 프로그램의 해당 규칙이 작동한다는 뜻이며, 의료 QA 성능이 좋다는 뜻이 아니다.

## 13. 보고서에서 사용할 수 있는 결론의 범위

적응형 방식의 잠정 전환율이 높다면 “이 모델과 이 문항·교란 범위에서 이전 응답을 활용한 생성이 더 많은 오류 후보를 찾았다”고 설명할 수 있다. 임상적 정답 보존이 검토되지 않은 후보까지 확정 공격으로 부르지 않는다.

Adaptive hard로 학습한 모델이 동일한 평가 세트에서 더 좋다면 “이 학습 예산과 평가 조건에서 해당 증강 데이터가 도움이 됐다”고 설명할 수 있다. 모든 의료 문제, 모든 공격, 다른 모델, 실제 환자에게도 효과가 있다는 결론은 나오지 않는다.

[PAIR](https://arxiv.org/abs/2310.08419)와 [MedFuzz](https://arxiv.org/abs/2406.06573) 등 기존 연구가 있으므로 적응형 교란 생성 자체를 새 알고리즘이라고 소개하지 않는다. 이번 과제의 기여는 제한된 데이터와 자원에서 생성·선별·학습의 효과를 구분하고, 재현 가능한 비교와 한계를 제시하는 데 있다.
